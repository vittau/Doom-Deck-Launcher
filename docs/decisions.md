# Decisions in force

Complements the decision table in `OVERVIEW.md` §2; entries here win where they differ.
Status: **Accepted** (decided) or **Proposed** (default until evidence or the owner says otherwise).

**D-034 authoring exception (owner, 2026-10-20; spec 062):** the owner subsequently requested
agent-written Flatpak packaging files and GitHub Actions builds. This authorizes an experimental
CI package with explicit AI-assisted provenance, overriding the human-only file-authoring
restriction for that package. It does not authorize a Flathub submission or make the generated
manifest eligible under Flathub's current policy. The Flathub submission restrictions below remain.

**D-035 — Signed self-hosted Flatpak channel (Accepted, owner, 2026-10-21).** Publish a dedicated
GPG-signed Flatpak repository and project page at
`https://www.vitormach.dev/Doom-Deck-Launcher/`, backed by this repository's `gh-pages` branch.
The owner agreed this with the Flatpak worker while the coordinator was unavailable and
confirmed the URL on resumption. D-039 subsequently replaces this original URL. Specs 062–063 implement the experimental build/install channel;
the existing GitHub tarball stays available. Flathub is a later option subject to its policies,
not the destination of these AI-assisted manifests. Spec 065 will replace the provisional page
with a launcher-themed page based on README, featuring a prominent `.flatpakref` install link.

**D-036 — Direct Play and base-game artwork (Accepted, owner, 2026-10-21).** Home Continue and
the main game-detail action launch the remembered/selected profile directly; Edit opens setup.
Red is reserved for actions that launch a game, superseding spec 060's red primary actions.
The owner explicitly requests DoomWiki menu/title artwork for base-game cards, a narrow
exception to D-020's no-id-assets rule; source/credit and image limits still apply. Spec 064
also records UI spacing/copy changes and automatic engine aspect with detected fullscreen
resolution; external-display behavior remains Needs Deck Validation.

**D-037 — Hardware renderer default (Accepted, owner, 2026-10-21).** Use DSDA-Doom's hardware
renderer for new/defaulted managed configurations, preserving player choices on migration.
The owner accepts the visual-fidelity tradeoff and reports a Deck measurement at 1080p/120 fps
on a TV: software CPU power around 4–5 W, hardware around half or less. This is owner-reported
CPU power for that scenario, not a total-system-power or battery-life claim. Confirm the engine
setting from pinned upstream source; implementation/tests are part of spec 064.

**D-038 — Independent catalog checked at each startup (Accepted, owner, 2026-10-21).**
Check the existing GitHub catalog source at every application opening, updating automatically
in the background while retaining the opt-out and safe offline cache/fallback. This replaces
D-025/spec 019's once-per-24-hour cadence. Discover shows a small effective-catalog source
timestamp in English UTC (for example `October 21, 2026 at 13:39 (UTC)`), rather than device
fetch time. Catalog publication stays independent of app releases; version gates only advance
when the catalog genuinely requires a newer client capability. Spec 077.

**D-039 — Dedicated domain and Flatpak identity (Accepted, owner, 2026-10-21).**
Use `https://doomdecklauncher.com/` as the canonical website and installation endpoint,
backed by the existing GitHub Pages publication. Use Flatpak ID
`com.doomdecklauncher.DoomDeckLauncher`. The owner explicitly authorizes replacing the old
ID and endpoint without a migration or compatibility alias because only the owner installed
that package. This replaces D-035's original URL and D-034's original ID; hosting, signing,
upstream downloads and unrelated state-schema/release compatibility checks stay in scope as
before. README recommends the signed Flatpak and points to the website for installation.
Spec 079.

| D-010 | **Community-contributable catalog.** Each mapset is one self-contained, human-readable TOML recipe under `catalog/` in this repository: sources (one or more packages from allowlisted hosts, with SHA-256), files to load and their explicit order, IWAD, complevel, DEH/BEX, credits and verification evidence. Adding a mapset is a pull request touching only that file (plus optional images with stated permission). CI validates every recipe with a `ddl` lint command (schema, hosts, hashes, order, references) and a `CONTRIBUTING.md` + PR template guide authors. Recipes may declare **optional components** (e.g. an add-on WAD), shown as per-profile toggles in the UI with their own load-order position. The UI must make it obvious which components are enabled and the resulting load order (e.g. main PWAD, then add-on) before launch.
