# Decisions in force

Complements the decision table in `OVERVIEW.md` §2; entries here win where they differ.
Status: **Accepted** (decided) or **Proposed** (default until evidence or the owner says otherwise).

| ID | Decision | Status |
| --- | --- | --- |
| D-001 | **License GPL-3.0-or-later.** Slint is used under its GPLv3 option, so no Slint attribution badge is required. | Accepted |
| D-002 | **Build and release on GitHub Actions.** Release binaries are built inside a pinned Steam Linux Runtime SDK container image. The owner tests on a physical **Steam Deck LCD** by downloading GitHub Release assets; there is no device access from development machines. | Accepted |
| D-003 | **Maximize work that needs no hardware.** Hardware-dependent behaviour sits behind traits with fakes; Deck checks are collected in `docs/deck-testing.md`. | Accepted |
| D-004 | **Docs in-repo only** (`docs/`, Markdown + `journal.yml`), spec-driven, no external trackers. | Accepted |
| D-005 | **Cargo workspace:** `crates/ddl-core` (logic, no UI deps) and `crates/ddl` (binary, Slint UI). | Accepted |
| D-006 | **Data formats:** TOML for hand-authored data (recipes, catalog, config templates), JSON for machine-written state. `serde_yaml` is unmaintained and not used. | Accepted |
| D-007 | **Engine versions:** by default DDL offers only DSDA-Doom releases whose SHA-256 is in DDL's reviewed list. Installing a newer unlisted release is an advanced action with a visible "not validated" warning. GitHub's asset digest proves transfer integrity, not independent trust. | Proposed |
| D-008 | **UI language:** English for the MVP, with every user-facing string translatable (Slint `@tr`). | Proposed |
| D-009 | **Pointer input inside DDL:** Steam Input layouts apply per shortcut, so a gyro/trackpad-as-mouse layout also drives DDL's own UI. DDL hides the cursor and ignores pointer motion without a click; navigation is gamepad-first. | Proposed — Needs Deck Validation |
| D-010 | **Community-contributable catalog.** Each mapset is one self-contained, human-readable TOML recipe under `catalog/` in this repository: sources (one or more packages from allowlisted hosts, with SHA-256), files to load and their explicit order, IWAD, complevel, DEH/BEX, credits and verification evidence. Adding a mapset is a pull request touching only that file (plus optional images with stated permission). CI validates every recipe with a `ddl` lint command (schema, hosts, hashes, order, references) and a `CONTRIBUTING.md` + PR template guide authors. Recipes may declare **optional components** (e.g. an add-on WAD), shown as per-profile toggles in the UI with their own load-order position. The UI must make it obvious which components are enabled and the resulting load order (e.g. main PWAD, then add-on) before launch. Every recipe declares its **base game** (required IWAD and accepted IWAD versions, e.g. Ultimate DOOM for SIGIL); the UI shows it on the mapset card and detail page together with whether the user has a matching IWAD. **Play is blocked** while the required IWAD is missing; the UI says which IWAD is needed and how to add it (install may still be allowed). Packages are usually archives (ZIP first): DDL downloads, verifies, safely extracts only the files the recipe names (paths inside the archive, case-exact), and arranges the load order itself — the user never unzips or orders files. End users see only the curated result: Install & Play. Required reference recipes: **AUGER;ZENITH** (Doomer Boards Project 37) with its optional add-on PWAD, and John Romero's **SIGIL** and **SIGIL II**. | Accepted |
| D-011 | **DSDA launch contract** (from `research/dsda-engine.md`). Every launch passes, as separate argv tokens: absolute `-iwad`; **one** `-file` list and **one** `-deh` list (DSDA keeps only the last occurrence of a repeated flag); explicit `-complevel` (omitting it falls back to a COMPLVL lump or MBF21); `-skill`; `-noautoload`; `-config <DDL-owned file>`; per-profile `-save`, `-data` and `-shotdir` directories created beforehand; a DDL-owned working directory. Pistol start is a per-launch `-pistolstart` (never combined with `-record`). The engine smoke test is `-v`. | Accepted |
| D-012 | **DSDA config ownership.** DSDA rewrites its whole config non-atomically on quit (and after a timedemo). DDL never writes the active config while DSDA runs; it provisions, backs up and merges only between runs, against a stored copy of the baseline it last applied (three-way merge). Per-profile scalar overrides use transient `-assign key=value`. | Accepted |
| D-013 | **Engine acquisition:** DDL downloads the unmodified official AppImage straight from upstream GitHub Releases into user storage, verifies size and SHA-256, and runs it as a separate program. If FUSE mounting fails, it falls back to `--appimage-extract` once and runs the full extracted AppDir's `AppRun`. DDL never mirrors or bundles the engine (GPL-2.0-or-later obligations would apply). | Accepted — Needs Deck Validation |
