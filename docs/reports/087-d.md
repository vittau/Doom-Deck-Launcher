## Composition and load order

- Every WAD embeds its `DEHACKED` patch and its music (`D_*` lumps: 14/35/11/35/21) and its own
  status-bar graphics. No recipe declares a separate `-deh` member, a music package or a status bar;
  each `main` component loads exactly one WAD. The test asserts one `-file` entry, empty `deh` list.
- `japanese-community-project` also declares the archive's optional `JPCP_HUD.wad` as
  `japanese-hud` (graphics, position 2, **off by default**), reproducing the authors' "load it with
  this wad for Katakana/Kanji status bar" instruction. Its 23 lumps were enumerated and are all
  status-bar graphics (`STBAR`, `STARMS`, `STTNUM0–9`, `WINUM0–9`).
  **Review note:** the lint's cosmetic allowlist does not include `WINUM*`, so a component label
  containing "status bar" would fail `--fetch` even though the file is cosmetic. The label is
  therefore "Japanese HUD graphics (Katakana/Kanji)" and the description states what it replaces; if
  the allowlist gains `WINUM*`, the label can change.
- Ozonia's `UMAPINFO` (3 episodes) is read by DSDA-Doom v0.30.1 and supplies the episode menu; the
  ZDoom-format `MAPINFO` in JPCP, Stardate and Ozonia is inert (ZDoom MAPINFO support was removed in
  v0.30.0), so no recipe prescribes a `-warp`.
- Abandon's WAD has 18 map markers but the authors list 17 levels; `MAP18` is a four-thing ending
  map (`HUSTR_18 = The End`). The recipe describes 17 released maps plus the ending map.

  review, together with the missing `WINUM*` allowlist entry.

  refers to that year's release. Both facts are in the recipe notes and limitations.
- **Needs Deck Validation for every title:** IWAD/complevel, load order, DEHACKED application,

  Katakana/Kanji HUD. For Abandon, performance and memory use are unmeasured — only inspected byte
  and thing counts are recorded; no FPS, frame-time, battery or thermal claim is made.
- **Spec items left open:** none for this worker; physical Deck validation is the remaining
  acceptance step (spec 087 A1–A5, 088 A1–A4, 089 A1–A4).
